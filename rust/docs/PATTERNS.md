# Patterns

## Runtime & Services

The `runtime` module defines the `Service` trait:

```rust
#[async_trait::async_trait]
pub trait Service: Send + 'static {
    type State: Clone + Send + Sync + 'static;
    async fn run(state: Self::State, shutdown_rx: watch::Receiver<()>);
    fn spawn(state: Self::State, shutdown_rx: watch::Receiver<()>) -> JoinHandle<()> { ... }
}
```

- Implement `run(state, shutdown_rx)` — get `spawn()` for free.
- Each service owns its own shutdown logic (select on `shutdown_rx.changed()`).
- `ShutdownHandle` listens for SIGINT/SIGTERM, broadcasts via watch channel, and waits for all handles.

Two services exist today: `HttpServer` and `TaskWorker`.

## Models

Models use private fields with public getters. Each model has three types:

- **Full type** (`User`, `Widget`) — all fields, returned by `find_by_*` methods.
- **ListItem** (`UserListItem`, `WidgetListItem`) — lightweight, returned by `list()`.
- **Patch** (`UserPatch`, `WidgetPatch`) — generated by `struct-patch`, Option fields for partial updates.

Update flow: `model.patch(patch, &db).await` applies only the fields that are `Some`.

## Handlers

One file per handler. Every handler file exports a single `pub async fn handler(...)`.

Organized by domain under `http/html/`:

```
widgets/
  views/    list.rs, show.rs, new.rs, edit.rs
  actions/  create.rs, update.rs, process.rs, archive.rs
admin/
  views/    dashboard.rs
  actions/  promote.rs, demote.rs
```

Top-level pages: `index.rs`, `login.rs`, `static_files.rs`.

Auth handlers follow the same pattern under `http/auth/`:

```
auth/
  google/   login.rs, callback.rs
  logout.rs
```

## Templates

Askama templates live in `crates/app/templates/`. Template structs are declared in the same file as the handler that uses them.

## Events

`EventBus` is a broadcast channel. Events are scoped:

- `Scope::User(Uuid)` — targeted to a specific user's SSE stream.
- `Scope::Broadcast` — sent to all connected clients.

Events use two-level serde tagging: `AppEvent::Widget(WidgetEvent)`.

## Tasks

Split into three parts: a trait, a producer, and a worker.

**`Task` trait** — each task type is self-registering:
```rust
pub trait Task: Serialize + DeserializeOwned + Send + Sync + 'static {
    const WORKER_NAME: &'static str;
    fn register(monitor: Monitor, db: Database, events: EventBus) -> Monitor;
    fn push(self, db: &Database) -> impl Future<Output = Result<(), anyhow::Error>> + Send;
}
```

- `TaskProducer` — generic client in `AppState`. `producer.push(task).await` works for any `Task` impl.
- `TaskWorker` — `Service` impl that chains `T::register(monitor, ...)` for each task type.

Tasks are domain-scoped: `tasks/widget/process.rs` defines `ProcessWidgetTask`.

Apalis stores all task types in the same Jobs table, keyed by `job_type`. Each type gets its own `SqliteStorage<T>` and named worker. No migrations needed when adding new task types.

## Database

- SQLite via `sqlx`.
- `DbUuid` newtype for UUID storage (stored as BLOB, implements sqlx Encode/Decode/Type).
- Migrations in `crates/app/migrations/` — includes vendor-copied Apalis migrations (marked "DO NOT MODIFY").

## Auth

Google OAuth with session-based auth. Session extractors in `http/auth/` provide `AuthUser` for protected routes.
